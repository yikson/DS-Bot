# 一次性 worker

- 日期：2026-11-01
- 相关：[2026-11 审计](../dev/2026-11-audit.md) 第 8 节；取代已关闭的 PR #46/#50（native workers）

## 为什么

Sir 的团队分三层：ADA（团队负责人）、每个项目一个长期 PM、N 个一次性 worker。ADA 和 PM 负责协调和验收，worker 负责执行。这样派活方的上下文不会被执行细节撑满，Sir 也不用盯着过程，成为全队的瓶颈，但随时可以围观。做法参考 [dsh-superagent](https://github.com/deepseek-ai/dsh-superagent-prototype) 的 Executor Session，只借思路，不复制代码。

## 已定的行为

**宿主**
- worker 就是一个 DSH Agent Session：侧栏 DSH Agent 下可以看到，Sir 可以围观，也可以直接在里面接着做。
- 它没有 Bot 身份，没有记忆，也没有团队工具（#45 的门禁已经拦住）。它不能派 worker，也不能给 Bot 发消息。
- 不设并发上限。

**派活方（ADA 和所有 Bot）**
- `start_worker({ title, brief, workdir? })`：
  - 新建一个 DSH Agent Session，标题为 `worker · <title>`；
  - `workdir` 是一个完整路径，不填就用派活 Bot 的工作文件夹；
  - 用配置里的 `workerPreset`，没配就用 DSH 的 `standard`；
  - 首条消息就是简报，末尾附上汇报要求；
  - 返回 worker id 和 Session id。
- `list_workers`：列出自己派出的 worker 及其状态。
- `message_worker({ worker, message })`：给 worker 补一条消息，它在下一步读到。
- `stop_worker({ worker })`：取消正在跑的回合，并把 worker 标为 `stopped`。

**worker 的汇报**
- `worker_report({ state, summary, evidence?, question? })`：
  - `state` 取 `ready`（完成）、`blocked`、`failed`、`dropped`（无需处理）之一；
  - 结果作为一张卡片，只投到派活的那个 Session（派活 Bot 的主干或任务 Session），不打扰别人；
  - 带 `question` 的汇报表示"需要决定"：派活方能答就用 `message_worker` 回答，答不了再问 Sir。
- worker 在 `ready`、`failed`、`dropped` 之后结束；`blocked` 之后保持打开，可以继续补消息。
- worker 结束回合时如果一直没有汇报，派活方会收到一张 `waiting` 卡片，附上 worker 最后说的话。

**可靠性（够用即可）**
- 瞬时模型失败的处理同 Bot：最多 3 次，间隔 15 / 30 / 60 秒。
- 重启后，正在跑的 worker 收到一条恢复提示："先检查目录、git 和外部状态，再决定是否重做"。
- 卡片投递失败时留在 worker 记录里，下次启动补投一次。没有账本。

**配置**
- `workerPreset`：可选，是 `cordis.patch.yml` 里定义的一个 `@deepseek-ai/dsh-agent-preset` 条目 id。建议在 `standard` 的基础上让前台命令 5 秒后转为后台，这样长命令运行时 worker 也能在下一步收到补充消息；DS Bot 不修改 DSH。

## 数据

- `state.agents[<DSH Agent>].workers[<id>]`，字段：
  - `sessionId`、`dispatcherSessionId`、`botId`；
  - `title`、`state`（`running` / `blocked` / `ready` / `failed` / `dropped` / `stopped`）；
  - `report`、`delivered`、`createdAt`、`updatedAt`。
- 团队还没有 DSH Agent 时自动建一个。旧的 DSH Agent 记录不受影响。

## 不做什么

- 不用 DSH 的 subagent（它绑在父回合上，结束即消失），也不做 worker 之间的协作。
- 不做 superagent 的 GitHub/飞书来源、Policy、面板。
- 不做 worker 的配额、优先级或并发槽位。

## 已知限制

- worker 能执行 shell，所以"不能派活"只是工具层面的限制，挡不住它另开一个进程或 CLI。
- 恢复提示不能保证外部操作不重复，靠 worker 自己检查。
