# 任务会话

- 日期：2026-10-30；2026-11-01 按[审计](../dev/2026-11-audit.md)缩为现状说明
- 相关：Issue #11，PR #12、#19–#31、#37、#38

## 为什么

长期 Bot（ADA 和各项目 PM）的主对话（主干）只应留下与用户的对话和每个任务一条结论。Bot 之间派活的过程放进任务专属的 Session，主干不被过程污染。多个任务并行时，每条消息都要落到对应任务的 Session。

## 已定的行为

**开关与资格**

- `taskSessionsEnabled: true` 是总开关；`taskSessions: [名字, …]` 列出可以开任务的 Bot。名字必须唯一匹配一个 Bot。
- `workBranches` 已停用：这项配置会被忽略；旧的分支记录原样留在 `state.json` 里，它们的 Session 仍可阅读。

**开任务**

- 一个 Bot 在自己的主干里用 `message_bot` 找另一个 Bot，并且双方都在名单里、不是群聊、不是 `reply_to: user` 时，自动开一个新任务；也可以显式写 `task: "new"`。
- 发起方的任务 Session 从它的主干 fork，只继承到最后一个已完成的回合；主干还没有已完成回合时改为新建。接收方用一个新的 Session。
- 任务的标题取派单内容的第一行，简报就是派单全文。每条任务消息都带上任务头（id、标题、简报）。
- `workdir` 只在开任务时有效，作为双方任务 Session 的工作目录。
- 不在名单里的 Bot 不开任务，消息照常走它的主干。

**任务内**

- 在任务 Session 里发的消息留在这个任务里，自动发到对方的任务 Session；不能借此给群或用户发消息，也不能跳到别的任务。
- 回复落到发起方的任务 Session，不进主干。
- 私信不插进用户可见的回合（no-steer）：Bot 之间的消息只在同一项私下工作的回合里才在下一步读到，否则排队等下一个回合。
- 任务内只能给本任务的两个参与者发消息；要找第三个 Bot，回到主干去找。
- `list_tasks` 列出自己的未关闭任务。
- 任务 Session 的记忆整理把简报和 Bot 之间的消息当作背景，不当作用户的决定。
- Bot 的能力（MCP）在任务 Session 里没就绪、而主干里同样没就绪时，只发警告，不阻塞开任务。

**关闭**

- 只有发起方的任务 Session 能 `close_task`。状态取 `done` / `blocked` / `cancelled` / `failed`；`done` 必须附证据；可选一个链接（URL、绝对路径或 Session 链接）。整条结论最多 1000 字。
- 关闭后取消这个任务里还在跑的回合，并把结论投到发起方的主干，显示为一张 Markdown 结论卡。
- 删除一个参与任务的 Bot 时，它的未关闭任务以 `failed` 结束。
- 任务关闭后才到的回复不再投递，只记一条警告。
- 重启后：开任务途中被打断的任务以 `failed` 结束；还没确认送达的结论先查发起方主干，主干里没有才补发一次。

**界面**

- 主干上方的 dock 任务栏列出任务；打开后，任务头显示派单内容。关闭后的任务可以从双方的 dock 重新打开查看。
- 侧栏显示 Bot 在任务里忙碌。
- DSH Agent 的 Session 不能用团队工具，包括任务工具。

## 数据

任务存在 `state.json` 的 `tasks` 里，键是任务 id。用户可见的字段：`title`、`brief`、`requester`、`assignee`、`state`、`participants`、`sessions`（Bot id → 任务 Session id）、`openedAt`、`closedAt`、`conclusion`、`delivery.state`。旧版本写下的其他字段原样保留。

## 不做什么

- 不在群聊里开任务。
- 不保证极端时序下结论只出现一次：主干恰好在投递途中换段时，可能多一张重复的结论卡。
